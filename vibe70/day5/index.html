34차시 · 왜

AI는 무엇을 바꿨는지 정확히 말해 주지 않는다

설명이 아니라 실제로 바뀐 줄을 본다
01부탁 안 한 파일까지서식 정리 · 이름 바꾸기 · 코드 지우기. 진짜 바뀐 줄이 수백 줄 속에 묻힌다
02새 파일이 생긴다로그 · 메모 · 백업 · 테스트 파일. 그대로 커밋하면 저장소가 더러워진다
03"고쳤습니다"의 함정바꾼 파일 목록을 빠뜨리거나 틀리게 말한다. 비밀 값 · 의존성 변경도 끼어든다
원칙 — 내가 읽지 않은 줄은 커밋하지 않는다. 커밋하는 순간 AI 코드는 내 코드다.
Claude Code, Gemini CLI, Codex 같은 코딩 에이전트는 폴더의 파일을 직접 고칩니다. 문제는 무엇을 바꿨는지 정확히 알려 주지 않는다는 것입니다. 부탁하지 않은 파일의 서식을 정리하거나 이름을 바꾸고, 로그나 메모 파일을 새로 만들고, 바꾼 파일 목록을 빠뜨리거나 틀리게 말하기도 합니다. 그래서 원칙은 하나입니다. 내가 읽지 않은 줄은 커밋하지 않는다. 커밋하는 순간 AI 코드는 내 코드가 됩니다.
34차시 · 순서

AI에게 맡기는 안전한 순서

기준점이 있어야 비교할 수 있고, 돌아올 수 있다
1폴더 정하기프로젝트 폴더 하나에서만 에이전트를 실행 (홈 · 바탕 화면 금지)
2기준점git commit 후 git switch -c ai-기능이름
3맡기기고칠 파일과 고치지 말 것, 새 파일 금지를 요청에 적는다
4찾기git status → git diff --stat → git difftool -d (Beyond Compare)
5골라 담기git restore · git clean -n/-f · git add 파일 · git commit -m "AI: …"
망쳤으면 → git switch main · git branch -D ai-기능이름 으로 통째로 버린다
순서는 다섯 단계입니다. 첫째, 에이전트는 프로젝트 폴더 하나에서만 실행합니다. 둘째, 맡기기 전에 커밋해서 기준점을 남기고 AI 전용 브랜치로 옮깁니다. 셋째, 요청에 고칠 파일과 고치지 말 것을 적습니다. 넷째, 끝나면 git status, git diff stat, 그리고 Beyond Compare로 바뀐 곳을 찾습니다. 다섯째, 원하지 않는 변경은 restore, 찌꺼기 파일은 clean으로 정리하고 원하는 파일만 add해서 커밋합니다. 결과가 엉망이면 main으로 돌아와 브랜치를 지우면 됩니다.
34차시 · 도구

Beyond Compare를 git에 연결하기

폴더 비교 한 화면으로 AI의 변경을 훑는다
# Windows (경로는 설치 폴더에 맞게)
git config --global diff.tool bc
git config --global difftool.bc.path "C:/Program Files/Beyond Compare 5/BComp.exe"
git config --global difftool.prompt false
git config --global merge.tool bc

# 쓰기
git difftool -d              # 바뀐 파일 전체를 폴더 비교로
git difftool -d main ai-menu # 합치기 전 브랜치 비교
빨강다른 파일 · 다른 줄
보라 · 파랑한쪽에만 있는 파일 (AI가 새로 만든 것)
화살표덩어리 단위로 원래 내용을 되가져오기
무료 대안WinMerge · VS Code 비교 · Meld
Beyond Compare 는 30일 체험판 뒤 라이선스 필요 · 자세한 실습은 Git · GitHub 실습 L23
비교 도구는 Beyond Compare를 씁니다. 두 폴더나 두 파일을 나란히 놓고 다른 곳을 색으로 보여 줍니다. git config로 diff tool을 bc로 정해 두면 git difftool 대시 d 한 줄로 바뀐 파일 전체가 폴더 비교 화면에 열립니다. 빨간색은 다른 곳, 한쪽에만 있는 파일은 AI가 새로 만든 파일입니다. 원하지 않는 덩어리는 화살표로 원래 내용을 되가져올 수 있습니다. 무료로는 WinMerge나 VS Code 비교 화면을 써도 흐름은 같습니다.
34차시 · 실습

세 도구로 같은 일을 시키고, 세 브랜치를 비교한다

누가 무엇을 몰래 바꿨는지 표로 남긴다
ai-claudeClaude Code브랜치에서 claude 실행 → 같은 요청
ai-geminiGemini CLI기준점에서 새 브랜치 → gemini
ai-codexCodex CLI기준점에서 새 브랜치 → codex
비교표 — AI가 말한 "바꾼 파일" vs git diff --stat · 부탁 안 한 변경 · 새 파일 · 최종 채택 여부
실습에서는 세 도구에게 같은 요청을 합니다. 기준점 커밋에서 ai claude, ai gemini, ai codex 세 브랜치를 만들고 각 브랜치에서 도구를 하나씩 실행합니다. 끝나면 AI가 말한 바꾼 파일 목록과 git diff stat의 실제 목록을 비교하고, 부탁하지 않은 변경과 새 파일을 표로 정리합니다. 가장 깨끗한 결과 하나만 골라 main에 합칩니다.
