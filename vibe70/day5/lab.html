34차시

검증 습관 · AI 코드 검토

14:50–15:40 · 세 도구 공통 · git · Beyond Compare

AI가 무엇을 바꿨는지 git과 Beyond Compare로 직접 찾고, 원하는 변경만 커밋합니다. 버전 관리 없이 AI에게 코드를 맡기지 않습니다.

STEP 1

Beyond Compare 설치와 git 연결

  1. scootersoftware.com/download 에서 Beyond Compare 5 를 받아 설치합니다. 30일 체험판으로 시작합니다(계속 쓰려면 라이선스, 무료 대안은 WinMerge).
  2. Git Bash 에서 git 과 연결합니다.
git config --global diff.tool bc
git config --global difftool.bc.path "C:/Program Files/Beyond Compare 5/BComp.exe"
git config --global difftool.prompt false
git config --global merge.tool bc
git config --global mergetool.bc.path "C:/Program Files/Beyond Compare 5/BComp.exe"
git config --global --get diff.tool
bc
macOS

앱을 연 뒤 메뉴 Beyond Compare → Install Command Line Tools, 그다음 git config --global diff.tool bc 만 합니다.

Windows 에서 그래픽하게 — TortoiseGit + Beyond Compare

명령 대신 탐색기 오른쪽 버튼으로 해도 됩니다. TortoiseGit Settings → Diff Viewer · Merge Tool 에 Beyond Compare 를 지정하고, Check for modifications(바뀐 파일 · 새 파일 목록) → 파일 두 번 누르기(Beyond Compare 비교) → Revert · Copy to Right 로 되돌리기 → Git Commit 에서 부탁한 파일만 체크. 설정 줄과 단계별 그림은 Git 실습 L23 · 실습 6 에 있습니다. STEP 2~5 의 명령 옆에 같은 메뉴를 적어 두었으니 GUI 로 따라가도 됩니다.

STEP 2

프로젝트 폴더 정하기와 기준점 커밋

누적 프로젝트 폴더로 이동합니다. 코딩 에이전트는 실행한 폴더를 작업 공간으로 삼으므로, 반드시 이 폴더 안에서 실행합니다. 홈 폴더나 바탕 화면에서 실행하지 않습니다.

cd ~/vibe-project          # 내 누적 프로젝트 폴더
git status                 # 커밋 안 한 것이 있으면 먼저 커밋
git add -A
git commit -m "AI 작업 전 기준점"
git switch -c ai-claude
기준점이 없으면

AI 결과가 마음에 들지 않아도 돌아갈 곳이 없습니다. AI 를 부르기 전에 커밋 — 이것이 오늘의 가장 중요한 습관입니다.

STEP 3

세 도구에게 같은 일 맡기기

세 브랜치를 모두 기준점에서 만들고, 브랜치마다 도구 하나를 실행해 같은 요청을 합니다.

git switch -c ai-claude main   # → claude 실행
git switch -c ai-gemini main   # → gemini 실행
git switch -c ai-codex main    # → codex 실행
요청 예시 — 고칠 파일과 금지할 것을 적는다 
내 프로젝트에 다크 모드 버튼을 추가해줘.
- index.html 에 버튼 하나, app.js 에 전환 함수, style.css 에 .dark 규칙만 추가
- 다른 파일과 기존 스타일은 고치지 말고, 새 파일은 만들지 마
- 끝나면 바꾼 파일과 바꾼 줄 수를 목록으로 알려줘
브랜치를 바꾸기 전에

도구 하나가 끝나면 그 결과를 git add -A · git commit -m "AI(claude): 다크 모드 — 검토 전" 으로 그 브랜치에 임시 커밋해 둡니다. 그래야 다음 브랜치로 옮겨도 결과가 섞이지 않습니다.

STEP 4

무엇이 바뀌었나 찾기

넓은 것에서 좁은 것으로. 어떤 파일이 → 얼마나 → 어떻게.

GUI: TortoiseGit → Browse References → main 과 ai-claude 를 함께 골라 Compare selected refs → 파일 두 번 누르기

git diff --stat main ai-claude       # 파일 목록과 줄 수
git diff --name-status main ai-claude # A 새 파일 · M 고침 · D 지움
git difftool -d main ai-claude       # Beyond Compare 폴더 비교
확인할 것보는 곳
AI 가 말한 "바꾼 파일" 과 실제 목록이 같은가--stat · --name-status
부탁하지 않은 파일 · 서식 변경Beyond Compare 폴더 비교의 빨간 파일
새로 생긴 파일 (로그 · 메모 · 백업)A 표시, 한쪽에만 있는 파일
지워진 코드 · 바뀐 함수 이름줄 비교의 빨간 줄
비밀 값 · 라이브러리 추가.env · package.json · requirements.txt 의 diff
STEP 5

골라 담아 main 에 합치기

세 결과 중 가장 깨끗한 브랜치 하나를 고릅니다. 그 브랜치에서 원하지 않는 변경만 되돌리고 다시 커밋한 뒤 main 에 합칩니다.

git switch ai-claude
git restore --source=main style.css   # 부탁 안 한 변경을 기준점 내용으로
git rm debug.log                    # AI 가 만든 찌꺼기 (임시 커밋에 들어갔던 것)
git commit -am "AI(claude): 다크 모드 — 검토 후 정리"
git switch main
git merge ai-claude
git branch -D ai-gemini ai-codex       # 쓰지 않은 시도는 버림
커밋 메시지에 남길 것

어느 AI 를 썼는지, 무엇을 부탁했는지, 무엇을 버렸는지. 나중에 이 커밋을 보는 사람이 어디를 더 의심해야 할지 알 수 있습니다.

STEP 6

먼저 연습해 보기 — Git 실습 L23

명령이 익숙하지 않으면 설치 없이 브라우저에서 연습합니다. Git · GitHub 실습 L23 · AI 가 만든 코드 검토하기 의 미션 3개(기준점 만들기 · 원하는 변경만 담기 · 망친 시도 버리기)를 풀고 오면 이 차시가 훨씬 빠릅니다.

이런 오류가 나면

오늘 가장 많이 나오는 것들입니다. 여기 없는 오류는 손을 드세요.

증상 · 메시지원인대응
명령을 찾을 수 없음 (command not found)설치가 안 됐거나 PATH에 없음터미널을 새로 열고 버전 확인. 그래도 안 되면 다시 설치
로그인 · 인증 오류계정 로그인이 풀렸거나 사용량 초과로그인 명령을 다시 실행하고 사용량 확인. 막히면 다른 도구로 진행
AI가 같은 실수를 반복맥락이 길어져 규칙을 놓침요약 후 새 세션에서 핵심만 다시 전달
git difftool 이 Beyond Compare 를 못 찾음difftool.bc.path 경로가 설치 폴더와 다름설치 폴더의 BComp.exe 경로를 / 로 적어 다시 설정 (예: C:/Program Files/Beyond Compare 5/BComp.exe)
AI 결과가 다른 브랜치와 섞임임시 커밋 없이 브랜치를 바꿈도구가 끝날 때마다 그 브랜치에 커밋한 뒤 switch
