Day 6 · 셸 스크립팅과 자동화

오늘 만드는 스크립트 두 개는 남은 나흘 동안 계속 씁니다. 동작하는 것이 아니라 남이 써도 되는 것을 목표로 하세요.

RULE 1

변수는 항상 큰따옴표

"$FILE" 이지 $FILE 이 아닙니다. 공백 하나로 스크립트가 망가집니다.

RULE 2

두 번째 줄은 set -euo pipefail

모든 스크립트에 넣습니다. 조용히 망가지는 것을 막아 줍니다.

RULE 3

-delete 전에 -print

Day 3의 규칙입니다. 지우기 전에 목록을 눈으로 봅니다.

PART 1

문법과 함정

13:00–13:50
MISSION 01

첫 스크립트

$ cd ~/ai-lab/scripts
$ cat > hello.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

NAME="${1:-세상}"
echo "안녕하세요, $NAME"
echo "오늘은 $(date +%F) 입니다"
EOF
$ bash hello.sh
$ bash hello.sh 리눅스
$ chmod +x hello.sh
$ ./hello.sh 폴리텍
기본값 문법

${1:-세상}은 "1번 인자가 없으면 '세상'을 쓴다"는 뜻입니다. set -u와 함께 쓰면 안전합니다.

MISSION 02

따옴표 함정 직접 겪기

$ cd /tmp && mkdir -p quotetest && cd quotetest
$ touch "my data.txt" other.txt
$ ls

$ FILE="my data.txt"
$ ls $FILE
ls: cannot access 'my': No such file or directory
ls: cannot access 'data.txt': No such file or directory

$ ls "$FILE"
my data.txt
이것이 rm 이었다면

rm $FILE은 my와 data.txt를 지우려 합니다. 우연히 그런 이름의 파일이 있으면 엉뚱한 파일이 사라집니다.

MISSION 03

조건과 반복

$ cd ~/ai-lab/scripts
$ cat > check.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

TARGET="${1:?경로를 지정하세요}"

if [[ -f "$TARGET" ]]; then
    echo "파일: $TARGET ($(wc -l < "$TARGET") 줄)"
elif [[ -d "$TARGET" ]]; then
    echo "디렉터리: $TARGET"
    for f in "$TARGET"/*; do
        [[ -e "$f" ]] || continue
        echo "  - $(basename "$f")"
    done
else
    echo "없습니다: $TARGET" >&2
    exit 1
fi
EOF
$ chmod +x check.sh
$ ./check.sh ~/ai-lab
$ ./check.sh ~/.bashrc
$ ./check.sh /없는경로; echo "종료코드: $?"
종료 코드

성공은 0, 실패는 0이 아닌 값입니다. $?로 확인합니다. 이게 있어야 다른 스크립트가 내 스크립트의 성공 여부를 판단할 수 있습니다.

MISSION 06

getopts로 옵션 받기

$ cat > clean_dataset.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

usage() {
    cat <<USAGE
사용법: $0 -i 입력.jsonl -o 출력.jsonl [-m 최소길이]
  -i  입력 JSONL 파일 (필수)
  -o  출력 파일 (필수)
  -m  최소 len 값 (기본 1)
  -h  이 도움말
USAGE
    exit 1
}

MIN=1
while getopts "i:o:m:h" opt; do
  case "$opt" in
    i) IN="$OPTARG" ;;
    o) OUT="$OPTARG" ;;
    m) MIN="$OPTARG" ;;
    h|*) usage ;;
  esac
done

[[ -z "${IN:-}" || -z "${OUT:-}" ]] && usage
[[ -f "$IN" ]] || { echo "[오류] 입력 파일 없음: $IN" >&2; exit 2; }

BEFORE=$(wc -l < "$IN")
jq -c --argjson m "$MIN" \
   'select(.response != "" and .len >= $m)' "$IN" 2>/dev/null \
   | jq -s 'unique_by(.prompt) | .[]' -c > "$OUT"
AFTER=$(wc -l < "$OUT")

echo "정제 완료: $BEFORE → $AFTER 줄 (제거 $((BEFORE-AFTER)))"
EOF
$ chmod +x clean_dataset.sh
$ ./clean_dataset.sh -h
$ ./clean_dataset.sh -i ~/ai-lab/datasets/dirty.jsonl -o ~/ai-lab/datasets/clean2.jsonl
$ ./clean_dataset.sh -i 없는파일.jsonl -o out.jsonl; echo "종료코드 $?"
Day 3이 도구가 되었습니다

손으로 치던 jq 파이프라인이 이제 옵션을 받는 재사용 가능한 도구가 됐습니다. 중복 제거까지 한 번에 처리됩니다.

AI LAB · 배치 러너와 정기 실행

15:40–17:10
MISSION 08

배치 러너 뼈대

$ cd ~/ai-lab/scripts
$ cat > prompts.txt <<'EOF'
리눅스에서 파일을 찾는 명령은?
파이프란 무엇인가요?
권한 644는 무슨 뜻인가요?
EOF

$ cat > batch_runner.sh <<'SCRIPT'
#!/usr/bin/env bash
set -euo pipefail

usage() { echo "사용법: $0 -p 프롬프트파일 -o 출력.csv [-n 반복]"; exit 1; }

N=1
while getopts "p:o:n:h" opt; do
  case "$opt" in
    p) PROMPTS="$OPTARG" ;;
    o) OUT="$OPTARG" ;;
    n) N="$OPTARG" ;;
    h|*) usage ;;
  esac
done
[[ -z "${PROMPTS:-}" || -z "${OUT:-}" ]] && usage
[[ -f "$PROMPTS" ]] || { echo "[오류] 파일 없음: $PROMPTS" >&2; exit 2; }

FAILED="${OUT%.csv}_failed.txt"
: > "$FAILED"
echo "prompt,round,elapsed,status" > "$OUT"

log() { echo "[$(date +%H:%M:%S)] $*"; }

ask() {            # 내일 이 함수만 진짜 API로 바꿉니다
    local q="$1"
    sleep 1
    [[ "${#q}" -gt 5 ]] || return 1
    echo "응답"
}

TOTAL=$(wc -l < "$PROMPTS"); OK=0; NG=0; i=0
log "프롬프트 ${TOTAL}개 × ${N}회"

while IFS= read -r line; do
    [[ -z "$line" ]] && continue
    i=$((i+1))
    for r in $(seq 1 "$N"); do
        start=$(date +%s)
        if ask "$line" >/dev/null 2>&1; then
            st=ok; OK=$((OK+1))
        else
            st=fail; NG=$((NG+1)); echo "$line" >> "$FAILED"
        fi
        el=$(( $(date +%s) - start ))
        echo "\"$line\",$r,$el,$st" >> "$OUT"
    done
    log "$i/$TOTAL 완료"
done < "$PROMPTS"

log "성공 $OK · 실패 $NG"
[[ $NG -gt 0 ]] && log "실패 목록: $FAILED"
SCRIPT
$ chmod +x batch_runner.sh
$ ./batch_runner.sh -p prompts.txt -o ~/ai-lab/logs/result.csv -n 2
$ column -s, -t < ~/ai-lab/logs/result.csv
내일 바꿔 끼울 곳

ask() 함수 하나만 진짜 API 호출로 바꾸면 그대로 동작합니다. 이렇게 바뀔 부분을 함수로 격리하는 것이 좋은 설계입니다.

MISSION 10

정리 스크립트와 cron 등록

$ cat > cleanup.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
LAB="$HOME/ai-lab"
LOG="$LAB/logs/cleanup.log"

echo "===== $(date +%F' '%T) 정리 시작 =====" >> "$LOG"
find "$LAB/logs" -name "*.log" -mtime +7 -print >> "$LOG"
find "$LAB/logs" -name "*.log" -mtime +7 -delete
find /tmp -maxdepth 1 -name "tmp.*" -mtime +1 -delete 2>/dev/null || true

echo "===== 정리 완료 =====" >> "$LOG"
EOF
$ chmod +x cleanup.sh
$ ./cleanup.sh && tail -10 ~/ai-lab/logs/cleanup.log

# cron 등록 — 테스트를 위해 매분으로 먼저
$ crontab -e
# 아래 한 줄 추가 (절대경로!)
# * * * * * /home/ubuntu/ai-lab/scripts/cleanup.sh

$ crontab -l
$ sleep 70 && tail -5 ~/ai-lab/logs/cleanup.log
확인 후 반드시 새벽으로 바꾸세요

매분 실행을 그대로 두면 로그가 계속 쌓입니다. WSL2에서 cron이 안 돌면 sudo service cron start를 먼저 실행하세요.

Day 6 체크리스트

  • shebang과 set -euo pipefail이 들어간 스크립트를 만들었다
  • 따옴표 없는 변수가 공백에서 쪼개지는 것을 직접 확인했다
  • if/for/while read를 각각 써 봤다
  • trap으로 Ctrl+C 상황에서도 뒷정리가 되는 것을 확인했다
  • getopts로 옵션을 받는 스크립트를 만들었다
  • -h로 사용법이 출력된다
  • xargs -P로 병렬 처리 시간을 측정해 비교했다
  • 배치 러너가 성공·실패를 구분해 기록한다
  • cleanup.sh가 동작하고 로그를 남긴다
  • cron에 등록해 실제로 실행되는 것을 확인했다
과제 06

재사용 가능한 배치 러너

제출: 익일 09:00

옵션을 받고, 실패를 견디고, 남이 써도 되는 스크립트를 완성하십시오.

제출 항목

각 항목마다 값과 사용한 명령을 함께 적을 것

  1. -p(입력) -o(출력) -n(반복) -h(도움말) 옵션 처리
  2. set -euo pipefail 과 trap 으로 안전장치
  3. 잘못된 인자 / 없는 파일 / 처리 실패 세 오류 처리
  4. 결과 CSV (입력, 결과, 소요시간, 성공여부)
  5. 실패 항목만 별도 파일로
  6. -h 로 사용법 출력
제출 양식 예시
$ ./batch_runner.sh
사용법: ./batch_runner.sh -p 프롬프트파일 -o 출력파일 [-n 반복]

$ ./batch_runner.sh -p 없는파일.txt
[오류] 입력 파일을 찾을 수 없습니다: 없는파일.txt
채점 기준

채점은 오류 상황 세 가지에서 스크립트가 어떻게 반응하는지로 합니다. 정상 동작은 기본이고, 실패했을 때 무엇을 남기는지가 실력입니다.
