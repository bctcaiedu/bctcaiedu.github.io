검색과 집계

오늘 배우는 도구 중 앞으로 가장 많이 칠 명령이 여기 있습니다.
첫 번째 블록입니다. 그렙은 앞으로 여러분이 리눅스에서 가장 많이 치게 될 명령 중 하나입니다. 수천 줄, 수십만 줄에서 원하는 줄만 골라내는 도구입니다.
grep

grep — 원하는 줄만 골라내기

$ grep error app.log              # error 가 들어간 줄
$ grep -i error app.log           # 대소문자 무시
$ grep -n error app.log           # 줄 번호와 함께
$ grep -c error app.log           # 개수만
$ grep -v error app.log           # error 가 없는 줄 (반대)
$ grep -r TODO ~/ai-lab           # 폴더 전체를 뒤져서
$ grep -A3 -B1 error app.log      # 앞뒤 줄까지 함께
-v 는 "반대로"입니다. 노이즈를 걷어낼 때 -v 를 이어 쓰는 일이 아주 많습니다.
그렙의 옵션은 일곱 개만 알면 실무의 구 할이 해결됩니다. 대시 아이는 대소문자 무시, 대시 엔은 줄 번호, 대시 씨는 개수만 세기입니다. 대시 브이가 중요한데요, 반대로 그 단어가 없는 줄만 남깁니다. 노이즈를 걷어낼 때 대시 브이를 계속 이어 붙이게 됩니다. 대시 알은 폴더 전체를 뒤지고, 대시 에이와 대시 비는 찾은 줄의 앞뒤 맥락까지 함께 보여 줍니다. 로그에서 에러를 찾을 때 앞뒤를 봐야 원인이 보이기 때문에 이 옵션을 자주 씁니다.
Regex

정규표현식 — 여섯 개면 시작할 수 있다

전부 외울 필요 없습니다. 이것부터 씁니다.
^줄의 시작^Error — Error로 시작하는 줄
$줄의 끝done$ — done으로 끝나는 줄
.아무 글자 하나a.c — abc, axc …
*앞 것이 0번 이상ab*c — ac, abc, abbc
[0-9]범위 중 하나숫자 한 글자
+ ? |확장 문법grep -E 를 붙여야 씁니다
+ 나 | 를 쓰려면 grep -E (또는 egrep). 이걸 몰라서 "왜 안 되지" 하는 경우가 많습니다.
정규표현식은 처음에 겁을 먹기 쉬운데, 여섯 개만 알면 시작할 수 있습니다. 캐럿은 줄의 시작, 달러는 줄의 끝, 점은 아무 글자 하나, 별표는 앞의 것이 영 번 이상, 대괄호는 범위 중 하나입니다. 여기서 흔한 함정이 하나 있습니다. 플러스나 세로막대 같은 확장 문법을 쓰려면 그렙에 대시 대문자 이를 붙여야 합니다. 이걸 모르고 왜 안 되는지 한참 헤매는 경우가 정말 많습니다.
find + xargs

조건에 맞는 파일을 찾아 일괄 처리

$ find ~/ai-lab -name "*.log"          # 이름으로
$ find /var/log -size +1M              # 1MB 넘는 것
$ find ~/ai-lab -mtime -1              # 하루 안에 바뀐 것
$ find ~/ai-lab -type d                # 디렉터리만

$ find ~/ai-lab -name "*.log" | xargs wc -l
$ find ~/ai-lab -name "*.tmp" -delete   # 조심해서
-delete 는 확인 없이 지웁니다. 반드시 -delete 없이 먼저 실행해 목록을 눈으로 보세요.
파인드는 조건으로 파일을 찾습니다. 이름으로, 크기로, 수정 시각으로, 종류로 찾을 수 있습니다. 여기에 엑스아그스를 이으면 찾은 파일들을 한꺼번에 처리할 수 있습니다. 주의할 것이 하나 있습니다. 파인드에 대시 딜리트를 붙이면 확인 없이 바로 지웁니다. 반드시 대시 딜리트 없이 먼저 실행해서 어떤 파일이 나오는지 눈으로 확인한 다음에 붙이십시오. 아홉째 날 디스크 정리 실습에서 이 습관이 사고를 막아 줍니다.
Block 2 · 11:10–12:00

sed · awk · jq · vim

찾았으면 바꾸고, 계산하고, 뽑아냅니다.
두 번째 블록입니다. 그렙이 찾는 도구였다면 이제는 바꾸고 계산하는 도구들입니다. 세 개를 다 깊이 배우지는 않습니다. 각각 한두 가지 쓰임만 확실히 익힙니다.
sed

sed — 찾아서 바꾸기

$ sed 's/error/ERROR/' app.log       # 각 줄의 첫 번째만
$ sed 's/error/ERROR/g' app.log      # 줄 안의 전부 (global)
$ sed -n '10,20p' app.log            # 10~20번째 줄만
$ sed '/^#/d' config.txt             # 주석 줄 삭제
$ sed -i 's/8080/11434/g' config.txt # 파일을 직접 수정
-i 는 원본을 덮어씁니다. 먼저 -i 없이 실행해 결과를 확인하세요.
세드는 찾아서 바꾸는 도구입니다. 에스 슬래시 찾을것 슬래시 바꿀것 슬래시가 기본 형태입니다. 끝에 지를 붙이면 한 줄 안의 모든 일치를 바꿉니다. 붙이지 않으면 각 줄의 첫 번째만 바뀌니 주의하십시오. 대시 아이를 붙이면 파일을 직접 고칩니다. 편리하지만 되돌릴 수 없으니, 반드시 대시 아이 없이 먼저 돌려서 결과를 눈으로 확인한 다음에 붙이는 습관을 들이십시오.
awk

awk — 컬럼을 다루고 계산하기

# 로그 한 줄:  epoch 12  loss 0.3421  acc 0.91

$ awk '{print $2, $4}' train.log      # 2번째, 4번째 컬럼
$ awk '$4 > 1.0' train.log            # 4번째 값이 1.0 초과인 줄
$ awk '{sum+=$4} END {print sum/NR}' train.log  # 평균
$ awk -F, '{print $1}' data.csv       # 쉼표로 구분된 파일
$1 $2 는 컬럼 번호, NR은 지금까지 읽은 줄 수입니다. 이 셋이면 평균·최대·개수가 다 됩니다.
오크는 표 형태의 텍스트를 다루는 도구입니다. 공백으로 나뉜 각 칸을 달러 일, 달러 이처럼 번호로 부릅니다. 특정 컬럼만 뽑을 수도 있고, 조건에 맞는 줄만 남길 수도 있고, 합계나 평균을 계산할 수도 있습니다. 엔알은 지금까지 읽은 줄 수를 담고 있어서 합을 엔알로 나누면 평균이 됩니다. 대시 에프로 구분자를 바꾸면 씨에스브이 파일도 다룰 수 있습니다. 오늘 오후에 학습 로그에서 로스 평균을 낼 때 바로 이걸 씁니다.
jq

jq — JSON을 명령줄에서 다루기

AI 데이터셋과 API 응답은 대부분 JSON입니다.
# data.jsonl 한 줄:  {"prompt":"...","response":"...","len":128}

$ cat data.jsonl | jq -r .prompt | head -3
$ cat data.jsonl | jq 'select(.len > 512)' | head
$ cat data.jsonl | jq -r '[.prompt, .len] | @tsv' | head
$ cat data.jsonl | jq -s 'length'         # 전체 개수
$ curl -s localhost:11434/api/tags | jq -r '.models[].name'
-r 은 따옴표를 뗀 raw 출력입니다. 파이프로 넘길 때는 거의 항상 -r을 씁니다.
제이큐는 제이슨 전용 도구입니다. 인공지능 쪽 데이터셋과 에이피아이 응답이 거의 다 제이슨이라 반드시 익혀야 합니다. 점 뒤에 필드 이름을 쓰면 그 값만 뽑고, 셀렉트를 쓰면 조건에 맞는 것만 남깁니다. 대시 알은 따옴표를 떼고 순수한 문자열로 출력하는 옵션인데, 파이프로 넘길 때는 거의 항상 붙입니다. 마지막 줄은 일곱째 날에 추론 서버를 띄운 뒤 실제로 쓰게 될 명령입니다.
vim

vim — 생존 문법만

서버에는 메모장이 없습니다. 설정 파일 하나 고칠 수 있으면 충분합니다.
i입력 시작글자를 칠 수 있게 됩니다
Esc입력 끝막히면 일단 Esc
:w :q저장 · 종료:wq 저장 후 종료
:q!버리고 나가기망쳤을 때의 탈출구
/단어검색n 으로 다음
dd줄 삭제u 로 되돌리기
gg G처음 · 끝긴 파일 이동

외울 것은 두 개입니다 — 막히면 Esc, 망쳤으면 :q!
뷔아이엠은 오늘 전부 배우지 않습니다. 서버에서 설정 파일 하나 고칠 수 있는 수준까지만 합니다. 아이를 누르면 글자를 칠 수 있고, 이에스씨를 누르면 빠져나옵니다. 콜론 더블유 큐로 저장하고 나가고, 망쳤으면 콜론 큐 느낌표로 버리고 나갑니다. 사실 외울 것은 두 개뿐입니다. 막히면 이에스씨, 망쳤으면 콜론 큐 느낌표. 이 두 개만 알면 뷔아이엠에 갇히지 않습니다.

학습 로그에서 loss 곡선 읽어내기

# train.log — 10만 줄
$ grep -c "epoch" train.log                       # 몇 epoch 돌았나
$ grep "epoch" train.log | awk '{print $2, $4}' | head
$ grep "epoch" train.log | awk '{print $4}' | sort -n | head -1   # 최저 loss
$ grep "epoch" train.log | awk '$4 > 5.0 {print NR, $0}'          # 발산 지점
$ grep "epoch" train.log | awk '{s+=$4} END {print s/NR}'         # 평균
십만 줄을 사람이 눈으로 훑는 대신, 다섯 줄로 답을 얻습니다.

지시학습 데이터셋 검증

모델에 넣기 전에 반드시 하는 일입니다.
1전체 개수jq -s 'length'
2빈 필드jq 'select(.response == "")'
3중복 프롬프트jq -r .prompt | sort | uniq -d

두 번째 과제는 데이터셋 검증입니다. 다섯 가지를 확인합니다. 전체 개수, 빈 필드, 중복 프롬프트, 길이 분포, 그리고 문법이 깨진 줄. 이건 선택이 아니라 필수 절차입니다. 이 다섯 가지를 확인하지 않고 학습을 돌리면 이틀을 기다린 뒤에 이상한 모델을 받게 됩니다. 그때 원인을 찾는 것보다 지금 오 분 쓰는 편이 훨씬 쌉니다.

오염된 데이터셋 정제 보고서

제공된 JSONL 데이터셋에는 문제가 섞여 있습니다. 파이프라인만으로 찾아내고 정제하세요.
01전체 레코드 수
02빈 response 필드 개수
03중복된 prompt 목록
04len 필드의 최솟값·최댓값·평균
05JSON 문법이 깨진 줄 번호
