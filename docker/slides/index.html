0장 · 컨테이너란 무엇인가?

코드 + 실행 환경을 한 꾸러미로

  • 프로그램은 코드뿐 아니라 실행 환경(언어 버전, 라이브러리, 설정)까지 맞아야 돕니다.
  • 가상 머신은 OS 를 통째로 띄우고, 컨테이너는 호스트 커널을 공유하는 격리된 프로세스라 가볍고 빠릅니다.
  • OCI 표준 덕분에 Docker 이미지는 쿠버네티스 · 클라우드 어디서든 돕니다.

1장 · 설치와 첫 컨테이너

docker 명령 한 줄 뒤에서 일어나는 일

  1. 요청 — docker run hello-world (클라이언트)
  2. pull — 이미지가 없으면 레지스트리(Docker Hub)에서 받기
  3. 생성 · 실행 — 데몬(dockerd)이 컨테이너를 만들고 켬
  4. 출력 전달 — 결과를 내 터미널로
Windows · macOSDocker Desktop (안에 리눅스 VM · WSL2)
Linux 서버Docker Engine

교수 노트 · 80분

  • 실제 PC 설치는 BIOS 가상화 · WSL2 업데이트에서 자주 막힙니다. 수업 전날 설치 과제로 내고, 수업 시간에는 가상 터미널로 진행합니다.
  • 미션: 데몬이 멈췄다! 다시 살리기 · 이름 붙인 웹 서버 켜기 · 새 형식 명령(docker container ls)으로 목록 보기.
2장 · 이미지 다루기

이름:태그, 다이제스트, 레이어

nginx = docker.io/library/nginx:latest

  • latest 의 함정 — 최신 보장이 아니고 시간이 지나면 바뀜 → 태그를 적어 고정
  • 태그는 옮겨 붙는 포스트잇, 다이제스트(sha256)는 바뀌지 않는 지문
  • 레이어 — 투명 필름을 겹친 것. 같은 층은 공유 → "Already exists"
  • tag 는 이름표만 추가(ID 같음), rmi 는 이름표를 떼고 마지막이면 삭제

  • 레이어 공유는 alpine 기반 이미지를 두 개 받아 "Already exists" 가 뜨는 것을 직접 보게 하면 한 번에 이해합니다.

4장 · 포트와 네트워크

-p 호스트:컨테이너, 그리고 이름으로 찾기

  • 컨테이너마다 자기 IP · 포트 · localhost 가 있습니다. 컨테이너 안의 localhost 는 그 컨테이너 자신.
  • -p 8080:80 — 왼쪽은 바깥(호스트), 오른쪽은 안. 127.0.0.1:8080:80 은 내 PC 에서만.
  • EXPOSE 는 문서일 뿐, 문을 여는 것은 -p.
  • 기본 bridge 는 DNS 가 없음 → docker network create 로 만든 네트워크에서는 컨테이너 이름으로 통신(내장 DNS).
"-p 했는데 접속이 안 돼요" 진단 순서① 포트 짝이 맞나 ② 앱이 127.0.0.1 에만 바인딩? → 0.0.0.0 ③ 포트 충돌 · 컨테이너가 꺼졌나
docker network create shop
docker run -d --name db --network shop redis:7-alpine
docker run --rm --network shop alpine ping -c 2 db

교수 노트 · 100분

  • 🚨 미션 세 개(이름으로 못 찾음 · Flask 접속 불가 · port is already allocated)는 반드시 풀게 합니다. 실무에서 가장 많이 만나는 장애입니다.
  • 컨테이너에서 호스트로 갈 때는 host.docker.internal.

6장 · Dockerfile 로 이미지 만들기

Dockerfile = 레시피

FROM python:3.12-slim
WORKDIR /app
# 의존성 먼저 → 캐시 재사용
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
# 코드는 나중에
COPY . .
EXPOSE 5000
CMD ["python", "app.py"]
  • docker build -t 이름:태그 . — 마지막 점(.)은 빌드 컨텍스트. COPY 는 그 안만 봅니다.
  • .dockerignore 로 비밀 · 대용량 파일을 뺍니다.
  • 레이어 캐시 — 한 단계가 바뀌면 그 아래는 모두 다시 → 자주 바뀌는 것을 아래로.
  • 서버는 host="0.0.0.0" 으로 띄워야 바깥에서 들어옵니다.
  • docker commit 은 기록이 안 남아 재현 불가 → 항상 Dockerfile.

교수 노트 · 120분

  • 캐시 시연: COPY 순서를 바꿔 두 번 빌드하고 CACHED 가 몇 줄 나오는지 비교합니다.
  • 🚨 미션: COPY 가 파일을 못 찾는다 · ModuleNotFoundError · 127.0.0.1 바인딩 — "빌드 실패는 ERROR [n/m], 실행 직후 종료는 logs, 접속 불가는 바인딩" 공식으로 정리.

8장 · 설정 · 자원 · 재시작

같은 이미지를 환경마다 다르게

  • 설정은 이미지 밖에 — 이미지 ENV(기본값) → --env-file → -e 순으로 덮어씀
  • 비밀번호를 이미지에 굽지 않기 — docker history 로 누구나 봄
  • 자원 울타리 — -m · --cpus · --pids-limit, docker stats 로 확인
  • 메모리 초과 → OOM(137, OOMKilled: true), CPU 초과 → 느려짐
재시작서버 앱은 unless-stopped
헬스체크"살아 있음"이 아니라 "일하고 있음". unhealthy 라고 재시작해 주지는 않음
로그json-file 은 끝없이 쌓임 → max-size · max-file
stop 10초PID 1 문제 → exec 형식 CMD · --init

교수 노트 · 120분

  • 미션 "OOM 재현하고 OOMKilled 확인하기"로 137 을 직접 만들어 보면 12장 디버깅이 쉬워집니다.
  • 환경 변수 설계는 5부 17장(BROKER · PREFIX · ME · THRESHOLD)의 기초입니다.

9장 · Docker Compose 기초

compose.yaml — 악보 한 장

services:
  web:
    image: nginx:1.27-alpine
    ports:
      - "${WEB_PORT:-8000}:80"
    depends_on: [cache]
    restart: unless-stopped
  cache:
    image: redis:7-alpine
    volumes:
      - cache-data:/data
volumes:
  cache-data:
  • 명령은 하이픈 없는 docker compose(V2), version: 키는 쓰지 않음
  • 프로젝트 이름 = 폴더 이름 → 폴더-web-1, 폴더_default
  • 같은 프로젝트끼리는 서비스 이름이 주소 (cache)
  • up -d · ps · logs -f · exec · down · down -v(볼륨까지)
  • .env + ${VAR:-기본값}, 검증은 docker compose config

교수 노트 · 100분

  • YAML 은 스페이스 2칸 · 탭 금지. 🚨 "YAML 들여쓰기 오류" 미션으로 config -q 검증 습관을 들입니다.
  • 우선순위: 셸 변수 > .env > 기본값 (퀴즈 단골).
10장 · Compose 실전

웹 · DB · 캐시 스택과 시작 순서

build: .
내 앱 올리기Flask + Redis 방문자 카운터. 코드를 고치면 up -d --build
healthcheck
DB 를 기다리기depends_on 은 순서만 → condition: service_healthy + 앱의 재시도

14장 · 컨테이너의 속

컨테이너는 결국 "그냥 프로세스"

네임스페이스
무엇이 보이는가pid · net · mnt · uts · ipc · user — 그래서 안에서는 내가 PID 1
cgroups
얼마나 쓸 수 있는가-m · --cpus 는 memory.max · cpu.max 파일에 적힘
overlay
층을 겹친 파일 시스템읽기 전용 이미지 층 + 쓰기 층, 수정은 copy-on-write

docker run 한 줄의 길: CLI → dockerd → containerd → shim → runc (OCI 표준) · 포트 게시는 veth · docker0 · iptables NAT · docker-proxy

Docker Desktop 은 리눅스 VM(WSL2) 안에서 컨테이너를 돌립니다. 볼륨 실제 위치: /var/lib/docker/volumes/이름/_data

교수 노트 · 120분

  • 심화 장입니다. 반 수준에 따라 이 슬라이드 + 미션 "호스트에서 컨테이너 프로세스 찾기" · "cgroups 한도를 파일로 확인하기" 두 개로 줄여도 됩니다.

17장 ① · Mosquitto 브로커 컨테이너

우리 반 MQTT 브로커를 1분 만에

# mosquitto/config/mosquitto.conf
listener 1883
listener 9001
protocol websockets
allow_anonymous true    # 강의실 안에서만
persistence true
persistence_location /mosquitto/data/
설정 파일이 없으면?Mosquitto 2 는 컨테이너 안 127.0.0.1 에서만 받습니다 — 4장의 바인딩 함정
docker run -d --name mqtt \
  -p 1883:1883 -p 9001:9001 \
  -v ./mosquitto/config:/mosquitto/config:ro \
  -v mqtt-data:/mosquitto/data \
  eclipse-mosquitto:2

docker exec -it mqtt \
  mosquitto_sub -t "aiot-kt2611/#" -v

1883 = ESP32 · Python · MQTT Explorer
9001 = 브라우저 대시보드 (WebSocket)

교수 노트

  • PowerShell 은 줄 끝 \ 대신 백틱, 바인드 경로는 ${PWD}/mosquitto/config. mosquitto_pub 의 JSON 따옴표는 PowerShell 5.1 에서 '{\"temp\":30}' 처럼.
  • 휴대폰 시뮬레이터(https)는 ws:// 로컬 브로커에 못 붙습니다 — 그래서 가짜 센서(③)가 필요합니다.
17장 ② ③ · 자동화 앱 이미지

설정은 환경 변수로, 주소는 서비스 이름으로

FROM python:3.12-slim
ENV PYTHONUNBUFFERED=1
WORKDIR /app
COPY requirements.txt .     # paho-mqtt==2.1.0
RUN pip install --no-cache-dir -r requirements.txt
COPY *.py .
RUN useradd --create-home app
USER app
CMD ["python", "auto_led.py"]
docker build -t aiot-app:1.1 ./app
docker network create aiot
docker network connect aiot mqtt
docker run -d --name auto-led --network aiot \
  -e BROKER=mqtt -e ME=s01 aiot-app:1.1
docker run -d --name sensor-sim --network aiot \
  -e BROKER=mqtt aiot-app:1.1 python sensor_sim.py
BROKER=localhost 는 틀린 답컨테이너 안의 localhost 는 자기 자신. 같은 이미지에서 명령만 바꿔 가짜 센서까지.

교수 노트

  • 먼저 공개 브로커(기본값)로 docker run --rm -e ME=s01 aiot-app:1.0 → 휴대폰 시뮬레이터 LED 가 켜지는 것을 보여 주면 "같은 이미지가 어디서든" 이 실감 납니다.
  • 확인은 MQTT Explorer(localhost:1883)에서 sensor 와 led 토픽이 번갈아 오가는지.
18장 · Compose 로 묶기

AIoT 스택을 compose.yaml 한 장에

services:
  mqtt:
    image: eclipse-mosquitto:2
    ports: ["1883:1883", "9001:9001"]
    healthcheck:
      test: ["CMD", "mosquitto_pub", "-h", "localhost",
             "-t", "health", "-m", "ok"]
  auto-led:
    build: ./app
    image: ${IMAGE:-aiot-app}:${TAG:-dev}
    environment: { BROKER: ${BROKER:-mqtt}, ME: ${ME:-s01} }
    depends_on:
      mqtt: { condition: service_healthy }
    restart: unless-stopped
  sensor-sim:
    image: ${IMAGE:-aiot-app}:${TAG:-dev}
    command: ["python", "sensor_sim.py"]
    profiles: ["sim"]
  dashboard:
    image: nginx:1.27-alpine
    ports: ["8080:80"]
    volumes: ["./dashboard:/usr/share/nginx/html:ro"]
상황.env · 실행
A 강의실 안에서만BROKER=mqtt
docker compose --profile sim up -d
B 휴대폰과 함께BROKER=broker.hivemq.com
docker compose up -d auto-led

대시보드
localhost:8080/?broker=ws://localhost:9001&id=s01

5부 · QUIZ

확인 퀴즈 클릭하면 정답

  1. 설정 파일 없이 eclipse-mosquitto:2 를 -p 1883:1883 으로 띄웠더니 MQTT Explorer 가 접속을 못 한다. 왜?
    → Mosquitto 2 는 설정이 없으면 컨테이너 안 127.0.0.1 에서만 받습니다. listener 1883 설정 필요.
  2. 같은 네트워크의 auto-led 가 브로커에 붙을 때 BROKER 값은?
    → mqtt (컨테이너 · 서비스 이름). localhost 는 자기 자신.
  3. profiles: ["sim"] 인 sensor-sim 은 언제 켜질까?
    → docker compose --profile sim up -d 처럼 프로필을 줄 때만.
  4. 팀 저장소에 올리면 안 되는 파일은? compose.yaml / .env.example / .env
    → .env (사람마다 다른 값과 키). 예시는 .env.example 로.
