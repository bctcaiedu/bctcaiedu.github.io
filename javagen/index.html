Overview

프로젝트 개요

한 문장으로: 요구사항 → 코드 생성 → 컴파일 → 테스트 → 실패하면 다시 생성을 자동으로 반복하는 HTTP 서비스를 만듭니다.

WHO
리눅스 과정을 마친 수강생셸·권한·프로세스·systemd 를 한 번씩 써 본 상태를 전제로 합니다. 자바는 기본 문법이면 충분합니다.
GOAL
AI 결과를 검증하는 구조작은 로컬 모델은 자주 틀립니다. 틀린 답을 걸러내고 스스로 고치게 만드는 고리를 직접 설계합니다.
RESULT
재부팅해도 살아 있는 서비스돌아가는 코드가 아니라 systemd 로 등록되어 자동 복구되는 서비스가 결과물입니다.

완성했을 때 이렇게 동작합니다

사람이 하는 일은 맨 처음 한 줄뿐입니다. 아래는 그 뒤에 서비스 안에서 실제로 오가는 내용을 순서대로 펼친 것입니다.

① 사람이 보낸 요청 — 이 한 줄이 전부입니다

② 모델이 처음 쓴 코드

Gugudan.java · 1차 시도
public class Gugudan {
    public static String print() {
        StringBuilder sb = new StringBuilder();
        for (int dan = 2; dan < 9; dan++) {          // ← 9단이 빠진다
            for (int i = 1; i <= 9; i++) {
                sb.append(dan).append(" x ").append(i)
                  .append(" = ").append(dan * i).append("
");
            }
        }
        return sb.toString();
    }
}

②부터 ⑥까지는 사람이 한 번도 끼어들지 않습니다. 서비스가 테스트 결과를 읽고 모델에게 다시 시킨 것입니다. 이 고리를 만드는 것이 이번 과제의 전부라고 해도 됩니다.

구구단처럼 쉬운 것도 작은 모델은 < 와 <= 를 자주 틀립니다. 사람이 눈으로 코드만 훑었다면 이 실수를 잡았을까요? 그리고 테스트도 모델이 썼다면 테스트가 통과했다는 사실은 무엇을 보장하고 무엇은 보장하지 못할까요?

모델을 잘 고르는 것이 핵심이 아닙니다. 검증 고리를 닫는 것이 핵심입니다. 7B 짜리 작은 모델도 에러를 돌려주며 두세 번 고치게 하면 쓸 만한 결과가 나옵니다.

Install

설치 과정

1일차 오전에 하는 작업입니다. 순서를 지키세요. 앞 단계가 안 됐는데 다음으로 가면 원인을 찾기 어려워집니다. 각 단계 끝에 확인 방법이 있으니 통과한 뒤 넘어갑니다.

STEP 0 · 설치 전 점검 10분

세 가지를 먼저 봅니다.

  • 가상화가 켜져 있는가 — 작업 관리자 → 성능 → CPU → 오른쪽 아래 "가상화: 사용". 사용 안 함이면 재부팅 후 BIOS 에서 Intel VT-x(또는 AMD SVM)를 켭니다.
  • 디스크 여유 — 60GB 이상. 모델 10~20GB, WSL 디스크, Gradle 캐시가 들어갑니다.
  • 그래픽 드라이버 — PowerShell 에서 nvidia-smi 가 동작하고 RTX 4070 이 보이면 됩니다.
Windows · PowerShell
nvidia-smi

STEP 1 · WSL2 와 Ubuntu 24.04 20분

PowerShell 을 관리자 권한으로 열고 실행합니다. 설치가 끝나면 Ubuntu 창이 떠서 사용자 이름과 비밀번호를 묻습니다. 이 비밀번호가 앞으로 sudo 할 때 쓰는 것이고, 입력할 때 화면에 아무것도 안 보이는 게 정상입니다.

Windows · PowerShell (관리자)
wsl --install -d Ubuntu-24.04
wsl --update
wsl --set-default-version 2
wsl -l -v

wsl -l -v 결과에 Ubuntu-24.04 가 Running · VERSION 2 로 보이면 성공입니다.

자주 나는 오류원인해결
0x80370102가상화가 꺼져 있음BIOS 에서 VT-x/SVM 활성화, Windows 기능에서 "가상 머신 플랫폼" 체크
0x800701bcWSL2 커널이 낡음wsl --update 실행 후 재시도
설치가 0% 에서 멈춤사내망·방화벽 차단네트워크를 바꾸거나 강사에게 오프라인 설치본 요청
이미 다른 Ubuntu 가 있음기존 배포판과 충돌이 과제 전용으로 새 배포판을 깔고 그 안에서만 작업

이미 WSL 을 쓰고 있다면 기존 배포판을 그대로 쓰지 마세요. 망가뜨려도 되는 전용 배포판을 따로 두는 편이 실습에 훨씬 편합니다.

STEP 2 · 자원 한도와 systemd 10분

WSL 은 그냥 두면 호스트 메모리의 절반까지 가져갑니다. 모델과 Gradle 이 같이 도는 환경이니 미리 정합니다. 메모장으로 C:\Users\<사용자>\.wslconfig 파일을 새로 만드세요.

.wslconfig · 강의실 PC(32GB · 24코어) 기준
[wsl2]
memory=16GB
processors=12
swap=8GB

이어서 Ubuntu 안에서 systemd 를 켭니다. 4일차에 서비스를 등록하려면 반드시 필요합니다.

Ubuntu (WSL) · 터미널
sudo tee /etc/wsl.conf <<'EOF'
[boot]
systemd=true
EOF
Windows · PowerShell — 설정 적용
wsl --shutdown
# 몇 초 기다린 뒤 Ubuntu 터미널을 다시 엽니다
Ubuntu (WSL) · 확인과 기본 업데이트
systemctl is-system-running        # running 또는 degraded
free -h | head -2                  # 메모리가 16G 로 잡혔는지
sudo apt update && sudo apt -y upgrade

systemctl 이 "System has not been booted with systemd" 라고 하면 wsl.conf 가 적용되지 않은 것입니다. 파일 위치와 철자를 확인하고 wsl --shutdown 을 다시 하세요.

STEP 3 · GPU 가 WSL 에서 보이는지 5분

Ubuntu (WSL) · 터미널
nvidia-smi

WSL 안에는 그래픽 드라이버를 설치하지 않습니다. Windows 드라이버가 그대로 전달되는 구조라서, apt install nvidia-driver-… 를 치면 오히려 GPU 가 사라집니다. 되돌리려면 배포판을 다시 깔아야 합니다. 안 보이면 ① Windows 드라이버를 최신으로 올리고 ② wsl --shutdown 후 다시 들어가 보세요. Ollama 만 쓸 것이라면 CUDA 툴킷도 따로 설치할 필요가 없습니다.

STEP 4 · Ollama 설치 15분

한 줄 설치 스크립트가 바이너리와 systemd 서비스까지 만들어 줍니다.

Ubuntu (WSL) · 터미널
curl -fsSL https://ollama.com/install.sh | sh
systemctl status ollama --no-pager
ollama --version

서비스는 ollama 라는 전용 계정으로 돌고, 받은 모델은 /usr/share/ollama/.ollama/models 에 쌓입니다. 동작을 바꾸려면 유닛을 직접 고치지 말고 덮어쓰기 설정을 만듭니다.

Ubuntu (WSL) · 설정 덮어쓰기
sudo systemctl edit ollama
# 편집기가 열리면 아래 세 줄을 넣고 저장합니다
# [Service]
# Environment="OLLAMA_KEEP_ALIVE=10m"
# Environment="OLLAMA_HOST=127.0.0.1:11434"

sudo systemctl restart ollama

OLLAMA_KEEP_ALIVE 는 마지막 요청 뒤 모델을 얼마나 메모리에 두는지입니다. 길게 두면 다음 요청이 빠르고, 짧게 두면 VRAM 이 빨리 풀립니다. 빌드와 번갈아 하는 우리 작업에는 어느 쪽이 나을까요?

systemctl status ollama 가 active (running) 이고, curl -s localhost:11434 가 Ollama is running 을 돌려주면 성공입니다.

STEP 5 · 코더 모델 받기 20분

VRAM 12GB(실사용 약 11GB)에 맞춰 고릅니다. 먼저 7B 로 시작하고, 여유가 있으면 14B 로 올려 비교해 보세요.

Ubuntu (WSL) · 모델 내려받기
ollama pull qwen2.5-coder:7b     # 약 4.7GB 내려받기
ollama list
ollama run qwen2.5-coder:7b "자바로 두 수를 더하는 메서드만 써 줘" --verbose

--verbose 를 붙이면 끝에 초당 토큰 수가 나옵니다. 이 숫자를 적어 두면 나중에 모델을 바꿨을 때 비교할 수 있습니다.

GPU 로 돌고 있는지 확인
ollama ps
# NAME                 SIZE     PROCESSOR    UNTIL
# qwen2.5-coder:7b     6.0 GB   100% GPU     9 minutes from now

PROCESSOR 가 100% GPU 여야 합니다. CPU 가 섞여 있으면 VRAM 이 모자란 것이니 더 작은 모델을 쓰거나 컨텍스트를 줄이세요.

이 프로젝트에서 쓸 설정(낮은 온도, 8K 컨텍스트, 출력 형식)을 고정한 파생 모델을 만들어 두면 코드에서 매번 옵션을 넘기지 않아도 됩니다.

~/javagen/Modelfile
FROM qwen2.5-coder:7b
PARAMETER temperature 0.2
PARAMETER num_ctx 8192
SYSTEM """
당신은 자바 코드 생성기입니다. 설명 없이 코드만 출력합니다.
패키지 선언 없이 public class 하나와, 그에 대한 JUnit 5 테스트 클래스를 작성합니다.
코드는 ```java 블록 안에만 넣습니다.
"""
Ubuntu (WSL) · 파생 모델 만들기
cd ~/javagen
ollama create javagen-coder -f Modelfile
ollama run javagen-coder "문자열을 뒤집는 메서드"

강의실 전체가 동시에 모델을 받으면 네트워크가 막힙니다. 강사가 나눠 준 모델 파일이 있으면 /usr/share/ollama/.ollama/models 에 복사한 뒤 소유자를 바꿔 주세요.

sudo cp -r models/* /usr/share/ollama/.ollama/models/ && sudo chown -R ollama:ollama /usr/share/ollama/.ollama

재시도 고리와 서비스화

실패를 다시 모델에게 돌려주어 고치게 만들고, 그 과정을 기록한 뒤 서비스로 등록합니다.

1. 재시도 고리

흐름
attempt = 1
반복 (attempt <= 3):
    코드 = 모델에게 요청(요구사항, 직전 코드, 직전 에러 요약)
    결과 = 컴파일 → 테스트
    기록에 추가(attempt, 단계, 에러 요약)
    통과면 중단
    아니면 attempt += 1
통과 못 하면 마지막 코드와 전체 기록을 함께 돌려준다
  • 재시도 프롬프트에는 직전 코드와 에러를 함께 넣습니다. 요구사항만 다시 주면 같은 실수를 반복합니다.
  • 세 번 모두 실패해도 500 을 내지 말고, 실패 사실과 기록을 정상 응답으로 돌려주세요.
  • 한 요청의 전체 시간 상한(예: 3분)을 따로 두면 운영이 편해집니다.

FAQ

자주 막히는 곳

GPU 가 안 잡혀요

WSL 안에 리눅스용 그래픽 드라이버를 설치했는지 먼저 확인하세요. 설치했다면 그것이 원인입니다. Windows 쪽 드라이버를 최신으로 올리고 wsl --shutdown 후 다시 들어가 보세요.

모델이 너무 느려요

ollama ps 에서 CPU 가 섞여 있으면 VRAM 이 모자란 것입니다. 더 작은 모델을 쓰거나 컨텍스트(num_ctx)를 줄이세요. Gradle 빌드와 동시에 돌리면 체감이 더 나빠집니다.

빌드가 유난히 오래 걸려요

프로젝트가 /mnt/c 아래에 있는지 확인하세요. 윈도우 디스크 쪽에 두면 파일 접근이 느립니다. ~/ 아래로 옮기면 바로 빨라집니다.

한글이 깨집니다

세 군데를 확인하세요. 모델 응답을 읽을 때의 문자셋, 파일로 저장할 때의 문자셋, javac -encoding UTF-8 옵션입니다.

서비스가 재부팅 후 안 떠요

정상입니다. WSL 은 PC 를 켠다고 저절로 뜨지 않습니다. 작업 스케줄러에 WSL 을 깨우는 작업을 등록했는지 확인하세요.

모델이 자꾸 설명을 섞어서 답해요

프롬프트 문제입니다. 형식 조건을 더 분명히 쓰고, 그래도 안 되면 후처리에서 코드 블록만 뽑아내세요. "형식을 지킨 비율"을 재 보면 프롬프트를 고칠 방향이 보입니다.
